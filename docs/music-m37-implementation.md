# M37 durable listening history

Stage: accepted after focused Chrome, Firefox and native Android verification
on 2026-10-27. The next full regression gate is after completed task 20 under
the user's ten-task cadence. Reviewed implementation: `3c1374f` (two review
rounds, first-round blockers repaired). Prerequisites `nj3`, `oj3` and `mk3`
were already accepted.

The qualified-play ledger retains the existing personal count and deduplication
behavior. A separate account-private history stores each qualifying occurrence,
including an explicit replay of the same track and a queued offline play. The
history endpoint orders by observed play time and ID; Settings offers recent
rows, recording on/off, 30/90/365-day or forever retention, and confirmed
Clear. Clear erases history without erasing personal counts. Web and Android
show loading, empty, retry and offline/error states. Account and access guards
limit the visible rows. This is a history view, not a Wrapped dashboard.

The web control uses the existing Settings disclosure and dialog focus rules;
native uses a labeled Settings section with touch controls and Back. The
retention and Clear confirmation remains visible until Save/Confirm or Cancel.
Narrow dark/light views were reviewed on both installed browsers and the
Android emulator. Neither web nor native overflowed or lost the primary
control in those views.

Playwright test with one worker, serially. Exact repeatable setup and command
are in `player-server/test/e2e-web/README.md` under M37. Chrome's regular
account keyboard-opened Replay Proof, produced captured 440 Hz audio and a

row. Firefox's admin account pointer-opened Distinct Proof, produced captured

One read-only Android 14/API34 emulator installed the same APK and connected
to that server through `adb reverse tcp:18837 tcp:18837`. The admin account
saved both long songs from the album to Downloads. With reverse removed and
both Wi-Fi and mobile data disabled, tapping the saved Replay Proof played a
real 440 Hz source for 66.3 seconds in QEMU output and showed paused position

server saw zero admin events while disconnected. On reconnect, exactly one

fixture restart preserved all three cross-account rows
(`server-restart-after-native.json`).

Native touch controls canceled a proposed 30-day retention change and kept
90 days, then saved 30 days. Recording off/on reached the API and showed the
paused state while off. Clear Cancel kept the event; Confirm removed only the
admin history. The album's personal play count remained two, the regular
account's two events remained, and the native screen showed “No recorded
plays.” `native-clear-confirm.png` and `native-cleared.png` record that flow.
