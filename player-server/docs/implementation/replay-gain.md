# M24 loudness interaction and processing

Implementation stage; Chrome, Firefox and native Android acceptance/output measurements await integrated verification.

Web player options: [Loudness: Off ▾] followed by a short live result. Off is the default and bypasses normalization. Track balances songs; Album keeps differences within an album. Automatic uses album tags for an ordered queue containing one album identity (valid release MusicBrainz ID first, otherwise normalized album plus album artist, Various Artists for compilations, or track artist); otherwise track. An expanded [Advanced loudness] disclosure contains labeled preamp and untagged gain controls, -12 to +12 dB, initially zero. Enter/Space activate the disclosure without invoking playback shortcuts; Escape closes it and restores summary focus before closing a compact player controls popover. Native player uses a labeled Loudness action and the same concepts in a scrollable bottom sheet with native dropdown/sliders and Back dismissal. Existing light/dark tokens and wrapping controls support narrow screens and large text.

States: Off → unity gain; enabled + valid tags → selected gain plus preamp; missing selected tag → untagged gain (no implicit cross-mode fallback); valid positive peak → cap gain to peak headroom; absent peak → cap at 0 dB and explain; no metadata → visible untagged/unknown-peak result. Automatic updates when shuffle/queue changes, including an owning detached popup. Detach load/state snapshots transfer in-memory settings and authoritative opener album context; live context messages reflect queue/shuffle edits without relying on the popup’s empty queue. Fresh popup state supplies settings on track changes and reattach before local playback resumes, including when localStorage is blocked. Normal storage events also refresh other windows. Browser processing unavailable/blocked → visible recoverable status; local processing never changes Cast output (explicit notice). Each track selection replaces gain before playback. Preferences persist on the device, independently of volume. Source retries, pause, speed, progress and queue ordering remain owned by existing playback code.

Web extends the existing single Web Audio graph: media source → gain → destination, with the existing analyser branching after gain. Native uses existing just_audio playback and player-volume attenuation. The Dart channel converts dB to integer millibels (100 mB = 1 dB); the native boundary validates 0–2400 mB and passes that value directly to Android. Positive gain attaches a caught native LoudnessEnhancer to that player’s current Android audio session through a small FlutterPlugin. Off never allocates an effect; allocation/update errors release it and report unavailable without failing source loading. Session changes replace the attachment, engine destruction releases it, and Activity detach preserves background playback. This avoids just_audio 0.9.46’s uncaught effect-allocation path; the player keeps its ordinary pipeline and source lifecycle. Device audio effects can be unavailable, which is reported rather than claiming normalization. Android system volume remains the user's volume control.

Local document-library items currently expose no embedded ReplayGain tags; they use the explicitly shown untagged policy. Indexed server streams and downloaded snapshots carry indexed tags. Peak limiting uses supplied metadata, not live loudness analysis or a guarantee against malformed tags/codec overshoots. Cast receiver normalization is unsupported. No new analysis or tag indexing is performed.
