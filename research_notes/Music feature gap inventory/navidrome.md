# Navidrome music server and built-in web UI feature inventory

## What released product and evidence does this inventory describe?

### Takeaway
This is a source-backed inventory of Navidrome **v0.64.2**, released **2026-09-24**, checked **2026-10-20**. It separates functionality present in Navidrome's own web interface from server APIs, optional integrations, and future work. It is an inventory from official documentation and a pinned release source checkout, not runtime browser verification.

### Cited Findings
- GitHub's latest-release API returned v0.64.2, published `2026-09-24T23:26:20Z`; its source commit is `101145742f4762164202cb4858c9126258bdc463`. All source links below are pinned to that tag. — [release](https://github.com/navidrome/navidrome/releases/tag/v0.64.2), [latest-release API](https://api.github.com/repos/navidrome/navidrome/releases/latest).
- The product is a self-hosted, multi-user music server with a responsive browser player and Subsonic-compatible API. The overview explicitly distinguishes general features from features supported by the Subsonic API. Do not turn every API endpoint into a built-in UI checkbox. — [official overview](https://www.navidrome.org/docs/overview/).
- Current documentation is ahead of some old overview wording: the overview still calls plugins a roadmap item, whereas the dedicated plugin documentation and v0.64.2 source implement plugins. Prefer dedicated docs/released source. — [plugin docs](https://www.navidrome.org/docs/usage/features/plugins/), [released plugin UI](https://github.com/navidrome/navidrome/tree/v0.64.2/ui/src/plugin).

### Inferences
- A finite public-source inventory cannot guarantee every minor behavior or hidden browser control; the detailed list below covers music capabilities and their user-facing controls. Its source-confirmed status does not mean the feature was tested in Chrome or Firefox.

### Gaps
- No Navidrome instance or audio library was run. Exact keyboard/screen-reader usability, device codec behavior, performance, and browser parity remain untested.

## Which music features are present in the built-in web UI?

### Takeaway
Navidrome offers a music-specific catalog, metadata-driven filtering, discovery collections, editable playback queues and playlists, synchronized lyric rendering, rating/favorite systems, sharing/download controls, and music administration. Some choices are configurable or depend on metadata/external agents.

### Inferences
- For Player comparison, several capabilities should be separate candidates: (a) proper song/album/artist metadata rather than generic file tags, (b) stored/editable playlists rather than a temporary ordered folder queue, (c) album/artist favorites and numeric ratings rather than one file-favorite flag, (d) collection shares and controlled downloads rather than a single-file share link.
- ND29 queue reorder/delete is source-confirmed through player library configuration and synchronization callbacks; no drag/drop runtime check was performed.

### Gaps
- No built-in Chromecast/AirPlay button or casting API was found in the released UI. Browser-provided tab casting and third-party-client casting must not be attributed to the built-in interface.
- No built-in UI controls for equalizer, playback speed, sleep timer, crossfade or gapless playback were found. The short per-play/pause volume fade in `Player.jsx` is not evidence of crossfade between tracks.
- No browser offline music-download/cache workflow found; service worker handles an offline error page. Do not confuse file downloads, server transcode cache or third-party offline clients with offline playback in the built-in UI.
- No built-in music-file tag editor or audio-upload library workflow found. Artwork upload and metadata refresh are narrower features.
- No claim of accessibility conformance is supported by these sources. Keyboard shortcuts and some ARIA attributes exist; comprehensive screen-reader/keyboard parity was not checked.

## Which additional features belong to the server/API or optional ecosystem, and what must be excluded?

### Takeaway
Navidrome's server supplies richer lyrics, interoperable APIs, persistent identity, scanning, authentication and plugin capabilities. Several useful candidates exist here, but they must be labeled separately from built-in web controls.

### Cited Findings
- **ND101 Subsonic/OpenSubsonic-compatible music API:** clients can browse/search, stream/transcode, download, manage playlists, rate/star, report plays, and use supported extensions. **ND102 Server get/save play queue for continuing in another client; ND103 audiobook-style bookmarks.** These are API features; no corresponding built-in browser server-queue-resume/bookmark controls were found. — [API routes](https://github.com/navidrome/navidrome/blob/v0.64.2/server/subsonic/api.go), [bookmark/queue handlers](https://github.com/navidrome/navidrome/blob/v0.64.2/server/subsonic/bookmarks.go).
- **ND104 Server lyrics ingestion/resolution:** sidecar `.ttml`, `.yaml/.yml` Lyricsfile, `.elrc`, `.lrc`, `.srt`, `.txt`; embedded TTML/Enhanced LRC/LRC/SRT/plain text; configurable priority; synced and unsynced forms; optional plugin lyric providers. **ND105 OpenSubsonic v2 enhanced word-by-word timing, multiple voices/languages and translations.** Richer client rendering is required; built-in browser mapper only handles synchronized line values. — [released README](https://github.com/navidrome/navidrome/blob/v0.64.2/README.md), [lyric service](https://github.com/navidrome/navidrome/tree/v0.64.2/core/lyrics), [v2 lyric response construction](https://github.com/navidrome/navidrome/blob/v0.64.2/server/subsonic/lyrics.go).
- **ND106 Jukebox playback to server audio hardware with compatible Subsonic remote clients and MPV; configurable devices; optional Snapcast routing.** Explicitly **not supported by built-in web UI**. — [jukebox docs](https://www.navidrome.org/docs/usage/features/jukebox/).
- **ND107 Optional acoustic similarity recommendations and sonic paths between songs via `sonicSimilarity` plugin capability/API.** This is distinct from standard UI song Instant Mix and artist radio; built-in UI uses `getSimilarSongs2`, not sonic-specific endpoints. — [sonic engine](https://github.com/navidrome/navidrome/blob/v0.64.2/core/sonic/sonic.go), [API handlers](https://github.com/navidrome/navidrome/blob/v0.64.2/server/subsonic/sonic_similarity.go), [UI mix endpoint](https://github.com/navidrome/navidrome/blob/v0.64.2/ui/src/common/playbackActions.js).
- **ND108 Experimental Jellyfin Music API:** allows compatible music clients to connect, off by default; optional LAN discovery, Quick Connect, session handling; it is a music API subset rather than a Jellyfin server/video dashboard. — [Jellyfin docs](https://www.navidrome.org/docs/usage/features/jellyfin/), [released API README](https://github.com/navidrome/navidrome/blob/v0.64.2/server/jellyfin/README.md).
- **ND109 Automatic library filesystem monitoring/scanning and scheduled scans; ND110 custom metadata tag mapping/types/splitting; ND111 configurable persistent IDs and move/retag recovery preserving playlist/rating/play-count links.** — [scanner source](https://github.com/navidrome/navidrome/tree/v0.64.2/scanner), [custom tag docs](https://www.navidrome.org/docs/usage/configuration/custom-tags/), [persistent ID docs](https://www.navidrome.org/docs/usage/configuration/persistent-ids/).
- **ND112 External authentication/reverse proxy integration; ND113 configurable download/sharing/artwork/user editing permissions; ND114 automated database backup and admin CLI.** These are operational features, usually lower priority than missing music playback/catalog features. — [authentication docs](https://www.navidrome.org/docs/usage/integration/authentication/), [configuration source](https://github.com/navidrome/navidrome/blob/v0.64.2/conf/configuration.go), [CLI source](https://github.com/navidrome/navidrome/tree/v0.64.2/cmd).
- **ND115 WASM plugin architecture** for external metadata agents, scrobblers, lyrics, event handlers, scheduled tasks, persistent storage and optional similarity; these are extension capabilities, not a guarantee that every service is included/configured out of the box. — [plugin docs](https://www.navidrome.org/docs/usage/features/plugins/), [plugin source](https://github.com/navidrome/navidrome/tree/v0.64.2/plugins).
- **ND116 Native full listening-history storage since 0.59.0.** Documentation describes statistics/analytics/“Wrapped”-style reports as future uses; **do not list Wrapped/statistics dashboards as existing UI**. — [scrobbling docs](https://www.navidrome.org/docs/usage/features/scrobbling/).
- **Excluded as absent/planned:** real filesystem-folder browsing is not supported (API simulates artist/album hierarchy from tags); built-in graphical smart playlist editor is planned; no current built-in Spotify integration (removed in 0.61.0). — [overview](https://www.navidrome.org/docs/overview/), [smart playlist docs](https://www.navidrome.org/docs/usage/features/smart-playlists/), [v0.61.0 release](https://github.com/navidrome/navidrome/releases/tag/v0.61.0).

### Inferences
- Highest-value comparison groups: music catalog and metadata; album/artist browsing; editable queue; playlists/smart rules; favorites/ratings/listen history; discovery; ReplayGain/transcoding; external scrobbling; music collection sharing/download controls; radio; API interoperability.
- Jukebox, plugin framework, custom authentication, server backups and Jellyfin API are valid server differences but should be scoped as optional infrastructure rather than prerequisites for a music-player backlog.

### Gaps
- No Player implementation was inspected by this researcher; parent/co-researcher must determine existing/partial/missing status from Player code and platform evidence.
- Most docs are mutable; pinned v0.64.2 source is authoritative for version-specific claims. No future/HEAD-only feature is counted.
